# LLera Product Language

## Essence

LLera MONOLITH OMEGA is a quiet local intelligence workspace. It should feel capable before it feels decorated: continuous, precise, calm under load, and honest about what it can do.

**MONOLITH means:** structural confidence, continuity, precision, depth, and stability.

**MONOLITH does not mean:** huge boxes, brutalist cards, thick borders, neon, cyberpunk, gaming hardware, terminal cosplay, or an engineering dashboard.

## Visual character

- **Quiet:** Most surfaces are tonal rather than outlined. Normal states do not compete for attention.
- **Precise:** Baselines align, hit targets are intentional, status language is exact, and risky actions name their effect.
- **Premium:** Depth comes from carefully stepped graphite surfaces, soft shadow, type rhythm, and small transitions.
- **Local:** Model and storage state are understandable, but internal paths and hashes remain in advanced details.
- **Capable:** Work progress is visible and interruptible without taking over the transcript.
- **Fast:** UI acknowledges input immediately, preserves scroll intent, and avoids layout animation.
- **Confident:** Copy is short and direct. The product never explains its own implementation on the home screen.

## Signature motif

LLera's mark is a restrained vertical aperture: two offset planes around a narrow light seam. It suggests depth and continuity without becoming an orb, mascot, or glowing AI cliché. The seam is used sparingly for active focus and current work.

## Color

Dark uses blue-graphite foundations rather than pure black. Light uses warm mineral white rather than inversion. The accent is a quiet mineral blue. Success, warning, and danger are reserved for real state.

## Typography

Segoe UI Variable is primary on Windows, with Inter and system sans fallbacks. Message body is 15px with generous line height. UI text is compact. Headings stay close to the content they organize and never become billboard-sized.

## Geometry

Corners are gently softened, not pill-shaped by default. The composer and transient menus receive the most elevation. Messages are mostly borderless; user turns use a subtle tonal plane. Reading width remains between roughly 760 and 880px.

## Motion

Transitions run 120–200ms using opacity and transform. Nothing bounces. Reduced-motion removes nonessential transitions. State remains understandable without animation.

## Voice

- Prefer: “Choose a local model to start.”
- Prefer: “LLera couldn't start the model.”
- Prefer: “Your task was interrupted. Your checkpoint is safe.”
- Prefer: “Review 6 file changes.”
- Avoid: internal class names, schemas, self-tests, wiring claims, raw verifier names, and generic “Something went wrong.”

## Default hierarchy

1. User goal and conversation.
2. Current work state and recovery action.
3. Attachments and produced artifacts.
4. Contextual mission/changes/evidence.
5. Runtime and diagnostics, only when requested or actionable.
